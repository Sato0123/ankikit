      handbook

      その日の学習を掘り出して、
      Anki カードにするまで

      対話で振り返り、記憶に残す価値のある部分だけをカードにする。カードは Markdown で書き、main にマージしたものだけが Anki に入る。

      01 / 正はファイル

      カードの正体は decks/ 配下の Markdown。Anki へは片方向に流し込むだけ。Anki 側で直しても戻ってこないので、直すときは Markdown を直して push し直す。

      02 / 承認 = マージ

      ブランチに書いただけのカードは Anki に入らない。main へのマージが承認そのもの。取り消したければマージ前に消すだけでいい。

      03 / push は main を読む

      ankikit push が見るのは作業ツリーではなく main の中身。「追加 0」と出たら、書けていないのではなくまだマージしていない。

      どこから読むか。 初めてなら はじめる → 毎日やることは 毎日の流れ → 書式を調べたいときは カードの書き方 → 動かないときは 困ったとき。

      はじめる

      置き場は 2 つに分かれている。 道具は誰にでも配れるが、カードはあなただけのもの。git の履歴は後から消せないので、混ぜない。

      道具 — public ankikitカード — private anki-decks
      中身src/ankikit/ tests/ docs/ decks/README.md（記法の仕様）decks/<slug>/（カード本体） anki.toml .claude/skills/
      触る頻度たまに（道具を直すとき）毎日（振り返り）

      以下の手順はすべてカード側で行う。find_repo_root() がカレントから上へ anki.toml / decks/ を探すので、その中に居れば環境変数は要らない。

        PC 版 Anki に AnkiConnect を入れる

        アドオンコード 2055492159（AnkiWeb）。入れたら Anki を再起動する。push のたびに Anki が起動している必要がある。

        道具を直しながら使うなら [tool.uv.sources] に ankikit = { path = "../Anki", editable = true }。直したそばから反映される。

        uv run ankikit install

        /anki-grill と /anki-initialize が .claude/skills/ に入る。スキルの正はパッケージの中（src/ankikit/skills/）なので、道具を更新したら配り直す必要がある。以降は ankikit update が入れ替えと配り直しをまとめてやる。手で直したスキルは --force が無ければ上書きされない。

        AnkiConnect のバージョンと、anki.toml のノートタイプ名が実在するかを出す。NG が出たら先に直す——ここを放置すると push で初めて転ぶ。直し方。

      毎日の流れ

      デッキを立ち上げるのは 1 デッキにつき 1 回だけ（/anki-initialize）。あとは学習した日の終わりに /anki-grill を回す。下がその 6 ステップで、横断する帯が承認ライン。

      あなたがやること

      • 質問に答える（観点を自分で列挙しなくていい）
      • カード候補の取捨を決める
      • マージしていいか答える — 承認はここだけ

      スキルがやること

      • 質問を出す・掘る
      • カードを書き、lint し、ブランチにコミットする
      • 承認後に approve と push を叩く

      手で書きたいときは decks/<slug>/cards/YYYY-MM-DD.md に直接足して、同じくマージしてから uv run ankikit push。経路が違っても承認ラインは同じ。

      skill

      2 つのスキル

      どちらも「対話 → カード → ブランチ → 承認 → push」で、違うのは何を掘るかだけ。呼び出したあとの主導権は向こうにあるので、ここは「何をされるか」だけ書く。細かい振る舞いは src/ankikit/skills/<name>/SKILL.md が正。

      /anki-initialize/anki-grill
      いつ新しいデッキを始めるとき（1 デッキ 1 回）学習した日の終わりに毎回
      掘る対象まだ何も起きていない領域。知らないことの発見今日あったこと。詰まった・間違えた・驚いた
      聞かれ方15〜25 個の論点を口頭でテストされる今日やったことを一問ずつ掘られる
      カードになるもの答えられなかったものだけ詰まった事実・判断の根拠
      裏面を書くのはモデル（このスキルだけの例外。1 枚ずつ正しさを確認される）あなたの言葉をそのまま使う
      枚数10〜20 枚 ＋ デッキ README5〜10 枚

      あなたが答えを持っておくとよいこと

      どちらのスキルも、答えに詰まると止まる質問がいくつかある。先に考えておくと速い。

      • 「今日はどのデッキ？」 — 話が複数デッキに散ると、デッキごとにブランチが分かれて往復が増える。1 セッション 1 デッキが基本。
      • 「それ、明日どこで使う？」 — 答えられないものはカードにならない。手を動かしていない知識はここで落ちる。
      • 「じゃあ説明して。3 行で」 — 「知ってる」には必ず説明を求められる。詰まった場所がそのまま最良のカードになるので、取り繕わないほうが得。
      • 「これで合ってる？」（initialize のみ）— モデルが書いた裏面の確認。判断できないものは「分からない」と言えば作られない。間違ったまま何か月も復習するのが一番損。

      何がカードになるか

      入れる

      • 今日詰まった・間違えた事実
      • 説明を求められて詰まったこと
      • 「へえ」と言った箇所
      • 判断の根拠（なぜ A ではなく B か）
      • よどみなく説明できたこと — ただし known: 付きの既習カードとして

      入れない

      • 調べれば 10 秒で出るリファレンス
      • 一覧・手順の丸暗記、文脈のない用語定義
      • 「明日使う場面」を答えられなかったもの
      • 会話に一度も出てこなかった論点
      • 既存カードと同じ表面

      答えられたことも捨てない。 今日答えられたことは半年後には忘れている。詰まったものは明日から出る新規カード、答えられたものは理解度に応じて何日か先から出る既習カードに分けて入る。

      途中で止めたくなったら

      「もういい」と言えば止まる。 それ以外に、向こうから切り上げる合図もある。

      起きていること意味
      3 往復、新しい事実が出ないその日の鉱脈が尽きた。切り上げてよい
      3 問続けて即答できた論点が浅い。スコープを一段上げる合図（initialize）
      3 問続けて「知らない」深すぎる。初期化より先に学習が要る
      候補が 10〜20 枚を超えた1 セッションの適量を超えている。残りは次回へ
      スキル側に課してある制約（デバッグ用）

      スキルが妙な動きをしたときに、何が破られたかを見るための一覧。

      • デッキを決めずに掘り始めない／質問を飛ばしていきなりカードを作らない
      • 承認なしで main にマージしない／--worktree で未承認のカードを push しない
      • ユーザーが言っていない知識を「補足」として勝手にカードにしない
      • decks/ 以外のファイルを一緒にコミットしない
      • 1 セッション 15 枚（初期化は 20 枚）を超えない
      • 答えを要約して返さない・相槌を打たない・一度に一問だけ
      • initialize: 論点リストを見せて自己申告させない（「知っているつもり」が素通りするため）／即答できたことをカードにしない／棚卸しの途中で解説を始めない
      • initialize: 方針を書かずにカードだけ作らない。ankikit new は stage より先
      デッキの粒度（initialize の要）

      デッキは「入れる基準が書ける粒度」でだけ切る。ここが決まらないと、以後の全セッションの判断がぶれる。

      粒度例症状
      広すぎプログラミング 英語入れる基準が「役に立つこと」にしかならない
      ちょうどreact-rendering sre-oncall meeting-english入れない基準を具体例で書ける
      狭すぎuseEffect の依存配列10 枚で尽きる。一段上げる

      カードの書き方

      デッキ 1 つ = ディレクトリ 1 つ。ここがカードの正で、Anki には片方向に流し込む。

      decks/ english-vocab/ README.md ← このデッキの方針（フロントマターが設定になる） cards/ 2026-08-20.md ← その日に足したカード 2026-08-21.md notes/ 2026-08-20-冠詞.md ← 学びの散文メモ。Anki には送られない

      カードファイル cards/YYYY-MM-DD.md

      --- tags: [meeting] # このファイル内の全カードに付くタグ（省略可） --- ## Q: circle back A: 後で改めて議論する <!-- 出典: 今日のMTGで上司が使った --> ## {{c1::defer}} to someone A: 人の判断に従う / 一任する tags: nuance ## Q: table a proposal A: 提案を棚上げにする（英と米で逆の意味になる） known: 3 # 既に答えられた ＝ 12 日後に初めて出る
      記法意味
      ## 行カードの開始 ＝ 表面。行頭の Q: は飾りなので取り除かれる
      A: 行ここから裏面。次の ## か EOF まで（複数行可）
      tags: 行そのカード固有のタグ。空白かカンマ区切り
      known: 行既に答えられた印（1〜4）。新規ではなく復習カードとして入る（下）
      <!-- ... -->ファイル内のメモ。Anki には送られない。カードに残したいなら A: の本文に書く
      {{c1::...}}表面に含めると穴埋めカードになる（ノートタイプが自動で cloze になる）

      書式チェックは uv run ankikit lint。フィールドは HTML として送られるので、改行は <br> に変換される。行頭の空白は落ちる。

      良いカードの形

      • 1 カード 1 事実。「かつ」「および」が入ったら分割する。
      • 表面は想起のきっかけ。 用語ではなく、実際に遭遇する状況の形にする。
      • 裏面は一文 ＋ なぜ。 理由が無いカードは忘れる。
      表面
      悪いuseEffect の依存配列
      良いuseEffect の依存配列に空配列を渡すと、いつ再実行される？

      答えられたことも忘れる — known:

      面談で即答できたことも、半年後には忘れている。 だからカードにする。ただし新規カードとして入れると、本当に知らなかったカードと同じ頻度で出てきて復習の枠を食う。known: を書くと 最初から「復習済み」の状態で Anki に入り、指定した日数が経って初めて出てくる。

      known:面談・振り返りでの様子最初に出るのは
      なし答えられなかった／誤解があった明日（ふつうの新規カード）
      1答えは出たが説明が詰まった2 日後
      2少し考えて答えられた5 日後
      3即答できた12 日後
      4毎日使っていて間違えようがない25 日後

      効くのは Anki 側でまだ一度も出ていないカードだけ。復習が始まったカードには二度と触らないので、何度 push しても学習履歴は壊れない（後から known: を足した場合も、まだ出ていなければ効く）。Anki には known::<数字> タグが付くので、後から絞り込める。

      忘れたものに付けない。 明日出るべきカードが 2 週間出てこなくなる。全部に付けると、ただの「出ないカードの山」になる。

      学びのノート notes/

      カードは 1 枚 1 事実なので、単元としての筋は残らない。障害の経過、設計を変えた理由、読み返したい話は decks/<slug>/notes/YYYY-MM-DD-<topic>.md に散文で書く。notes/ は Anki には送られない（push も lint も cards/ しか読まない）。

      学習状況 ankikit status

      uv run ankikit status <slug> # 画面に出すだけ uv run ankikit status <slug> --write # README の学習状況ブロックを書き換える

      ファイル側（枚数・既習の内訳・未マージ・ノートの索引）と Anki 側（新規 / 学習中 / 復習 / 定着 / 今日出る / 忘れ直しの多いカード）をまとめる。書き換えるのは <!-- ankikit:status --> マーカーの中だけなので、手で書いた方針は消えない。README を開けば「ああこの単元ね」と思い出せるのがねらい。

      デッキ README.md

      フロントマターが設定、本文が方針。本文は /anki-grill が読んで「何をカードにするか」を判断する材料になるので、入れる基準と入れない基準は具体例で書く。

      --- anki_deck: "英語::語彙" # Anki 上の実デッキ名。:: で階層。省略時はディレクトリ名 note_type: basic # basic | cloze（カードに {{c1::}} があれば自動で cloze） tags: [english] # このデッキの全カードに付くタグ --- ## 目的 ## 入れる基準 ## 入れない基準 ## 要点（この単元は何だったか） ## 前提（既に押さえていること） ## カードの作り方 ## 運用メモ ## 学習状況 # ankikit status --write が書き換える

      ## 要点 は後から開いて「ああこの単元ね」と思い出すための場所。5〜10 行で骨格だけ書き、詳しい話は notes/ に回す。

      ## 前提 は /anki-initialize の棚卸しで答えられた論点を残す場所。以後の /anki-grill がこれを読み、同じことを二度と聞かない。ただしカードとしては known: 付きで入っているので、忘れたころに Anki が出してくる。

      雛形は uv run ankikit new <slug> --anki-deck "英語::語彙" で作れるが、新しいデッキは /anki-initialize から始めるのが本筋（方針と最初の 10〜20 枚をまとめて作る）。

      直したいとき

      同一カードかどうかは表面のハッシュで判定する（Anki 側に ankikit-uid::<hash> タグが付く）。表面が IDだと思えば、下の挙動はすべて素直に読める。

      直した場所push したときの挙動
      裏面だけ既存カードを更新。学習履歴は維持される
      表面別カードとして追加される。古い方は Anki に残るので手で消す
      カードを削除Anki からは消えない。手で消す（push は追加と更新しかしない）
      同じ表面を 2 回lint がエラーにする

      英単語 — JSON から一気に流し込む

      english-vocab デッキだけは対話も承認面談も通さない。本から拾った単語に「今日どこで詰まった？」と聞く意味は無いので、自分で JSON に打ち込んで ankikit eng に食わせる。検証・重複除外・decks/ への追記・コミット・Anki への反映まで 1 コマンドで走る。

      uv run ankikit eng words.json # 検証 → 重複除外 → 追記 → コミット → Anki uv run ankikit eng words.json --dry-run # 何が登録され何が弾かれるかだけ見る uv run ankikit eng words.json --tag duo3 # 全カードに出典タグを付ける

      承認の原則は形を変えて残っている。eng は main 上でしか push しないので、「Anki にあるもの ＝ main にあるもの」は崩れない。他のブランチで書くだけなら --no-push。

      入力 JSON

      本から手で打ち込む前提の形式。配列だけでも、設定つきのオブジェクトでも受ける。

      { "tags": ["duo3"], # 全カードに付くタグ（省略可） "words": [ {"word": "anyway", "sentence": "Let's try anyway.", "meaning": "とにかく"}, {"word": "circle back", "sentence": "She circled back to me.", "note": "p.42"}, {"word": "wake", "sentence": "I ____ up early.", "meaning": "目を覚ます"} ] }
      キー意味
      word / 単語必須。覚えたい語。空欄の答えになる
      sentence / 例文必須。出会った文をそのまま。____ を書けばそこが空欄、書かなければ word を文中から探す
      meaning / 意味日本語の訳。省略可
      note / メモ出典ページや語法メモ。省略可

      できあがるカード

      ## Let's try ____. # 表面 = 例文の該当語を空欄にしたもの A: anyway # 裏面 = 単語 / 意味 / 完全な例文 / メモ とにかく Let's try anyway. tags: word::anyway # ← 重複判定のキー。消すと同じ単語が二重に入る

      目標は「anyway = とにかく」を思い出すことではなく、文の中の穴を埋められるようになること。だから表面は単語ではなく例文になっている。

      空欄化のルール

      入力どうなるか
      例文に ____ があるそこが空欄。不規則変化（wake → woke）はこれで書く
      そのままの語があるその語を空欄にする。大小は無視（Anyway も可）
      素直な語形変化circle → circled、stop → stopped 程度までは追う
      見つからないその 1 件だけエラー。答えが表面に見えるカードは作らない

      1 件の不備で全体は止まらない

      重複判定はこのデッキだけ単語で行う（他のデッキは表面のハッシュ）。Circle Back と circle-back は同じ語。壊れた行と重複だけ落として、残りはそのまま登録するので、同じファイルに追記しながら何度流してもよく、直した行だけが後から入る。全部止めたいときは --strict。

      ERROR [5] woke: 例文に 'woke' が見つからないので空欄にできません。… ERROR [6] defer: sentence が空です 重複: [4] Anyway: ファイル内の [1] と同じ単語なので飛ばしました english-vocab → 英語::語彙: 入力 7 件 / 登録 4 / 重複 1 / 不備 2
      終了コード意味
      0全件そのまま登録できた
      1登録はしたが、飛ばした行がある
      21 枚も作れない（ファイルが無い / JSON が壊れている / main に居ない / Anki 未起動）

      JSON が壊れていたら行・桁とその行の中身を出す。全角の ： や末尾の余分なカンマといった手打ちの定番はヒントまで出る。

      何を入れるか

      入れる

      • 読んでいて意味が取れずに止まった語
      • 意味は知っていたが、その文での使われ方が意外だった語
      • 例文が本文からそのまま取れる語（自作の例文より、出会った文）

      入れない

      • 例文なしの単語（この形式に載らない）
      • 固有名詞、専門用語そのもの
      • 既にこのデッキにある語（word:: タグで自動的に弾かれる）

      1 ファイル 20〜40 語くらいが読み返しやすい。本の章ごとに分け、--tag duo3 のように出典をタグに入れておくと後で絞り込める。

      status [slug]学習状況のまとめ（ファイル側 ＋ Anki 側）--write（README に書き戻す）
      new <slug>デッキの雛形作成--anki-deck "親::子" --note-type basic|cloze
      stage <slug>staging/<slug> に切り替え—
      lint書式チェック（作業ツリー）--deck <slug>
      pendingまだ main に無いカードを一覧--deck <slug>
      approve [slug]staging を main に --no-ff マージ（＝承認）--branch <name>
      push承認済みのカードを Anki へ反映--deck --dry-run --force -v --worktree
      eng <file.json>英単語 JSON をカードにして Anki まで（詳細）--deck --tag --date --dry-run --strict --no-commit --no-push -v
      installスキルをこのリポジトリに配置--list --force
      updateankikit 自身を最新にする（詳細）--dry-run --force --no-install --target
      change-version <版>ankikit のバージョンを指定して入れ替える--list --dry-run --force --no-install --target
      doctorAnki 接続とノートタイプ名の確認—

      全コマンド共通: --ref <branch> で「承認済みとみなすブランチ」を変えられる（既定 main）。
      decks/ が無くても走るのは new install update change-version doctor の 5 つだけ。他は decks/ を見つけられないと理由を言って止まる。

      push --worktree は承認を無視して作業ツリーを送る非常口。これを使うと「Anki にあるもの ＝ main にあるもの」が崩れる。通常は使わない。

      道具を新しくする

      カード側は ankikit を git 依存として固めた時点のまま使っている。道具を直しても、こちらから取り直さないかぎり古いままで、スキル（/anki-grill など）はさらに install を叩き直すまで入れ替わらない。ankikit update はその 2 つをまとめてやる。

      uv run ankikit update # 最新を取り直して、スキルも配り直す uv run ankikit update --dry-run # 何を叩くかだけ見る（何も変えない） uv run ankikit update --force # 手で直したスキルも上書きする

      中でやっているのは uv lock --upgrade-package ankikit → uv sync → uv run ankikit install の 3 つ。最後が子プロセスなのは、入れ替えた直後の自分自身にはまだ古いスキルが載っているから。走り終わると、どのコミットからどのコミットへ動いたかが出る。

      バージョンを選ぶ — change-version

      新しい道具で挙動が変わったときに、いつでも戻せるようにするためのもの。タグ・ブランチ・コミットのどれでも渡せる。

      uv run ankikit change-version --list # 取得元にあるタグとブランチを見る uv run ankikit change-version v0.2.0 # そのタグに固定する uv run ankikit change-version 3e3a566 # そのコミットに固定する uv run ankikit change-version latest # 固定をやめて最新に追従する

      固定している間は update が動かない。固定を黙って外して最新に飛ばす方が危ないので、理由（tag=… / rev=…）を言って止まる。最新に戻すのは change-version latest。

      pyproject.toml の書き方update の挙動
      { git = "…" }既定ブランチの最新へ。これが普通
      { git = "…", branch = "…" }そのブランチの最新へ
      { git = "…", tag = "…" } / rev = "…"動かない。change-version で外す
      { path = "../Anki", editable = true }入れ替えるものが無い（直したそばから効く）。スキルの配り直しだけ走る

      カードには一切触らない。触るのはカード側の pyproject.toml / uv.lock / .claude/skills/ の 3 つだけで、decks/ は読みもしない。

      困ったとき

      よく出る症状と、その場の直し方。ほとんどは「main に居ないか、Anki が起きていないか、名前が違うか」の 3 つに落ちる。

      症状何が起きているかどうする
      push が「追加 0」 カードは書けているが、まだ main にマージされていない。push は main しか読まない ankikit pending で確認 → ankikit approve <slug>
      AnkiConnect に接続できません PC 版 Anki が起動していない／アドオン未導入。カードは main にあるので無事 Anki を起動して ankikit push を叩き直すだけ。作業は巻き戻さない
      ノートタイプ名でエラー anki.toml の名前が、あなたのコレクションに実在しない（UI 言語や導入経緯で変わる） ankikit doctor の出力を見て [note_types] を直す。英語 UI の例
      decks/ が見つかりません カード側リポジトリの外で叩いている。黙って 0 件にはならず、どこを探したか言って止まる ~/anki-decks の中で叩く。どうしても外からなら ANKI_REPO_ROOT
      直したはずのカードが二重に増えた 表面を変えた。表面のハッシュが ID なので、別カードとして追加される Anki 側で古い方を消す。裏面だけの修正なら履歴を保ったまま更新される
      Anki で直した内容が消えた 正は decks/ の Markdown。push は片方向で、Anki 側の編集は戻らない Markdown を直して push し直す
      lint が重複エラー 同じ表面のカードが 2 枚ある 片方を消すか、表面を書き分ける（表面が ID なので同居できない）
      stage が失敗する decks/<slug>/ がまだ無い 先に ankikit new <slug>（本筋は /anki-initialize）
      approve が止まる decks/ に未コミットの変更が残っている 先にコミットする。マージは常にコミット済みの状態から
      install してもスキルが古いまま 手で直したスキルは守られて上書きされない 捨てていいなら ankikit install --force。中身を見るだけなら --list
      eng で一部の語だけ入らない 仕様。壊れた行と重複だけ落として残りは通す エラー行を直して同じファイルをもう一度流す。既に入った語は重複で自動的に飛ぶ
      スマホに来ない push が届くのは PC 版 Anki まで PC 版で同期（AnkiWeb）→ スマホ側でも同期

      迷ったらまず 2 つ。 uv run ankikit decks（どのデッキに何枚あって、何枚が未マージか）と uv run ankikit doctor（Anki と話せているか）。ここまでで大半は切り分けられる。

      Anki 本体の設定

      ここから先は ankikit ではなく Anki 側の話。構造は 4 層で、設定もこの階層ごとにある。デッキ自体は学習アルゴリズムの数値をほぼ持たない——それを持つのはデッキオプション（プリセット）で、複数デッキで共有できる。

      デッキ (Deck) カードの置き場 └─ カード (Card) ノートタイプのテンプレートから自動生成 └─ ノート (Note) フィールドにデータが入っている実体 └─ ノートタイプ (Note Type / Model) フィールド定義＋カードテンプレート定義

      まずここだけ

      1. アルゴリズムは FSRS。 Deck Options の一番下で ON。目標保持率 90% から始め、レビュー 1000 件を超えたら Optimize で個人最適化。
      2. 学習ステップは 1 日以内に収める。 FSRS 導入後、長い学習ステップは非推奨（1m 10m で十分）。
      3. 新規カードは少なめから。 10〜20 枚 / 日で始め、こなせるようなら増やす。
      4. Maximum reviews/day は絞りすぎない。 低いと復習が繰り越され、雪だるま式に増える「隠れ滞留」を招く。
      5. フラグ・タグは学習順序に影響しない。 優先度を変えたいときは Reposition かフィルタデッキ。
      デッキオプション（プリセット）の全項目

      歯車アイコン → Options。1 つのプリセットを複数デッキに割り当てられるのがポイント。性質の違うデッキは別プリセットにする。

      グループ主な項目
      Daily LimitsNew cards/day ／ Maximum reviews/day（大きめ推奨）／ 親子デッキ間での上限の共有
      New CardsLearning steps（例 1m 10m）／ Order（追加順・ランダム）／ Insertion order
      LapsesRelearning steps ／ Leech action（サスペンド or タグのみ）／ Leech threshold ／ Minimum interval
      Display OrderNew/review order ／ Interday・Intraday learning order ／（FSRS 時）Ascending retrievability
      Burying同じノートから生成された兄弟カードの重複出題を抑制（new / review / interday）
      FSRS有効化（グローバル）／ Desired retention（0.70〜0.97、目安 90%）／ FSRS parameters（Optimize）／ Maximum interval ／ Historical retention
      SM-2 専用Starting ease ／ Easy bonus ／ Interval modifier ／ Graduating interval ／ Easy interval（FSRS 有効時は非表示）
      Easy Days曜日ごとに Normal / Reduced / Minimum。間隔計算後の微調整で、過去には遡及しない
      ノートタイプ（Note Type / Model）

      「Manage Note Types」から管理。フィールド構成とカードテンプレートのセットで、デッキとは独立（同じノートタイプを別デッキで使い回せる）。

      • フィールド: 名前・並び順、表示フォント、Sticky（次の追加時に内容を保持）、Sort field（並び替え・重複チェックの基準）
      • カードテンプレート: Front / Back Template（{{フィールド名}} で挿入、{{FrontSide}} で表面を引き継ぎ）、Styling (CSS)、条件付き表示 {{#フィールド}}...{{/フィールド}}
      • 1 つのノートタイプから複数枚のカードを自動生成できる（単語→意味 / 意味→単語）
      • 特殊: Cloze（{{c1::語句}}）／ Basic (and reversed card) ／ Image Occlusion
      • Change Note Type: 既存ノートをフィールド対応させながら別ノートタイプへ移行
      カードの状態とメタ値
      状態説明
      New未学習
      Learning / Relearning学習中・再学習中（短期間隔）
      Review卒業後、長期間隔で復習中
      Suspended一時停止（出題対象外）
      Buriedその日だけ非表示
      • メタ値: Due ／ Interval ／ Ease factor（SM-2）・Stability / Difficulty（FSRS）／ Reps・Lapses ／ Flag ／ Tags
      • 操作: Forget（New に戻す）／ Set Due Date ／ Reposition ／ Find & Replace
      フィルタデッキ・全体設定

      フィルタデッキは検索条件でカードを一時的に集める特殊デッキ（例 is:due tag:英単語）。「Reschedule based on my answers in this deck」を外すと、元のスケジュールに影響を与えず一時演習だけできる。

      全体設定 (Preferences): Scheduler v3 ／ Next day starts at（日付の切り替わり時刻）／ Show next review time ／ AnkiWeb 同期 ／ バックアップ世代数 ／ 表示設定。

      出典: Anki 公式マニュアル（Deck Options / Note Types）および 2026 年時点の FSRS 関連ガイド。元文書は docs/anki-reference.md。

      実装メモ

      ここから下は道具を直す人だけ読めばよい。使うだけなら不要。

      どこに何があるか

      パス役割
      src/ankikit/ライブラリ層（parser → deck → sync → connect、承認判定は approval）
      src/ankikit/vocab.py英単語 JSON の検証・例文の空欄化・重複キー（ankikit eng の中身）
      src/ankikit/commands/サブコマンド 1 つ = 1 モジュール。cli.py は組み立てるだけ
      src/ankikit/skills/スキルの正。ankikit install がここからカード側へ配る
      decks/README.mdカードファイルの記法（カードそのものではなく仕様）
      docs/handbook.htmlこのページ。build_pages.py が包んで GitHub Pages へ
      tests/uv run pytest

      サブコマンドを足す

      commands/ にファイルを 1 つ作り（NAME / HELP / add_arguments(parser) / run(args) -> int）、commands/__init__.py の ALL に並べる。cli.py は触らない。 decks/ が無くても走るコマンドには NEEDS_DECKS = False を置く（既定 True）。

      踏みやすいところ

      • カードの置き場は config.find_repo_root() が決める。 ANKI_REPO_ROOT → カレントから上へ anki.toml / decks/ を探す → 開発時のパッケージ 2 つ上、の順。依存として入れると 3 番目は site-packages を指すので当てにできない。
      • approval.decks_at(ref) は git archive で ref 時点の decks/ を一時展開する。push はそこを読む。一時ディレクトリなので、カードの読み込みは必ず with の中で終わらせる。
      • 同一カード判定は表面のハッシュ（ankikit-uid::<hash> タグ）。ただし english-vocab だけは単語（word::<単語> タグ）。
      • フィールドは HTML。改行は to_html() で <br> に変換してから送る。行頭の空白は落ちる。
      • 接続先は ANKI_CONNECT_URL（既定 http://localhost:8765）で差し替えられる。

      anki.toml（英語 UI の場合）

      既定値は日本語 UI 用（basic = 基本［表面 / 裏面］、cloze = 穴埋め問題［Text / 裏面追記］）。config.py の DEFAULTS を anki.toml が項目単位で上書きする。

      [note_types.basic] model = "Basic" front = "Front" back = "Back" [note_types.cloze] model = "Cloze" front = "Text" back = "Back Extra"
