# Anki 設定完全リファレンス
 
Anki の構造は「**デッキ**（カードの置き場）」「**ノートタイプ**（フィールドとテンプレートの定義）」「**ノート**（データの実体）」「**カード**（表示される1枚1枚）」の4層に分かれる。設定もこの階層ごとに存在する。
 
```
デッキ (Deck)
 └─ カード (Card) ← ノートタイプのテンプレートから自動生成
     └─ ノート (Note) ← フィールドにデータが入っている実体
         └─ ノートタイプ (Note Type / Model) ← フィールド定義＋カードテンプレート定義
```
 
---
 
## 1. デッキ (Deck)
 
### 1.1 デッキの種類
| 種類 | 説明 |
|---|---|
| 通常デッキ | 手動で作成し、階層化（`親::子`）できる。サブデッキは無制限にネスト可能 |
| フィルタデッキ (Filtered Deck) | 条件式で他デッキからカードを一時的に集める特殊デッキ（§4参照） |
 
### 1.2 デッキ自体が持つプロパティ
- **名前**（`::` で親子関係を表現、例: `英語::単語::TOEIC`）
- **説明 (Description)**：デッキ選択画面や学習開始画面に表示するメモ
- **紐付けられているオプションプリセット**（後述）
> ポイント：デッキ自体は「学習アルゴリズムの数値」をほぼ持たない。それらは次の「デッキオプション（プリセット）」が保持し、複数デッキで共有できる。
 
---
 
## 2. デッキオプション（プリセット）
 
歯車アイコン → Options で開く画面。**1つのプリセットを複数デッキに割り当てられる**のがポイント（例："標準"プリセットを全言語学習デッキに適用）。
 
### 2.1 Daily Limits（1日の上限）
| 項目 | 内容 |
|---|---|
| New cards/day | 1日に新規導入するカード枚数の上限 |
| Maximum reviews/day | 1日の復習枚数の上限（詰まり防止に大きめ・実質無制限が推奨されることが多い） |
| 新規カードを毎日ボーナスとして繰越 / 制限を全サブデッキで共有 等 | 親子デッキ間で上限をどう扱うかの設定 |
 
### 2.2 New Cards（新規カード）
- **Learning steps**：新規カードが「卒業」するまでの間隔列（例 `1m 10m`）
- **Order**：新規カードの出題順（追加順 / ランダム）
- **Insertion order**：キュー内での挿入順
### 2.3 Lapses（失敗時の再学習）
- **Relearning steps**：復習カードで「Again」を押した際の再学習ステップ
- **Leech action**：一定回数失敗し続けたカードを「サスペンド」か「タグ付けのみ」にするか
- **Leech threshold**：リーチ判定に使う失敗回数
- **Minimum interval**：再学習後に付与する最小間隔
### 2.4 Timer / 表示
- **Show answer timer**：解答時間を画面に表示するか
- **Stop timer on answer**：解答表示時にタイマーを止めるか
### 2.5 Display Order（出題順序）
- **New/review order**：新規と復習を混ぜる順（新規優先、復習優先、混在 等）
- **Interday/Intraday learning order**：日をまたぐ学習カードの並び順
- （FSRS有効時）**Ascending retrievability**：忘却確率が高い順に出題
### 2.6 Burying（間引き）
- **Bury new siblings**：同じノートから生成された新規カードの重複出題を抑制
- **Bury review siblings**：同上（復習カード版）
- **Bury interday learning siblings**：同上（日またぎ学習カード版）
### 2.7 Audio
- **自動再生 (Autoplay)**
- **音声のスキップ動作**（表側・裏側で自動再生するか等）
### 2.8 Advanced / FSRS（スケジューラ設定）
| 項目 | 内容 |
|---|---|
| **FSRS の有効化** | 全プリセット共通のグローバル設定。SM-2（旧来アルゴリズム）から切替 |
| **Desired retention（目標保持率）** | FSRS の最重要パラメータ。0.70〜0.97程度。高いほど復習量が増え記憶は強くなる（目安90%） |
| **FSRS parameters（学習済みパラメータ）** | Optimize ボタンでレビュー履歴から個人最適化（推奨：レビュー1000件以上で実行、数か月ごとに再最適化） |
| **Maximum interval** | FSRS が付与しうる最長間隔 |
| **Historical retention** | 過去データが不足する場合の仮定値 |
| SM-2専用項目（FSRS有効時は非表示） | Starting ease／Easy bonus／Interval modifier／Graduating interval／Easy interval など |
 
### 2.9 Easy Days（曜日別の負荷調整）
- 曜日ごとに **Normal / Reduced / Minimum** を指定し、特定の曜日の復習量を抑制（間隔計算後に微調整するだけで、過去の間隔には遡及しない）
### 2.10 その他
- **New cards ignore review limit** などの細かい相互作用オプション
- **v3 scheduler** の有効化（新しいキュー処理エンジン。通常はデフォルトで有効）

## 3. ノートタイプ（Note Type / Model）
 
「Manage Note Types」から管理。**フィールド構成とカードテンプレートのセット**であり、デッキとは独立した概念（同じノートタイプを異なるデッキで使い回せる）。
 
### 3.1 フィールド (Fields)
- フィールド名・並び順の定義（例：`表面` `裏面` `例文`）
- **Font（表示フォント・サイズ・RTL方向）**：入力画面での見た目
- **Sticky**：次のノート追加時に内容を保持するか
- **Sort field**：ブラウザでの並び替え・重複チェックの基準フィールド（通常1つ目のフィールド）
- **Excludeしない/Collapsed**：フィールドを畳んで表示するか
### 3.2 カードテンプレート (Card Types)
1つのノートタイプから**複数枚のカード**を自動生成できる（例：単語→意味／意味→単語の双方向カード）。
| 項目 | 内容 |
|---|---|
| **Front Template** | 表面のHTML（`{{フィールド名}}` で挿入） |
| **Back Template** | 裏面のHTML（`{{FrontSide}}` で表面を引き継ぎ可能） |
| **Styling (CSS)** | 全テンプレート共通のスタイル定義 |
| **Card count（何枚生成するか）** | テンプレートを追加するほどノート1件から複数カードが生成される |
| **条件付き表示** | `{{#フィールド}}...{{/フィールド}}` でフィールドが空なら非表示にできる |
 
### 3.3 特殊ノートタイプ
- **Cloze（穴埋め）**：`{{c1::語句}}` 構文で1つのフィールドから複数の穴埋めカードを自動生成
- **Basic (and reversed card)**：表裏両方向のカードを標準搭載
- **Image Occlusion**：画像の一部を隠して出題（近年標準搭載）
### 3.4 その他ノートタイプ管理
- Add/Clone/Rename/Delete（既存ノートタイプの複製・改変）
- **Fields の追加・削除・並び替え**（既存ノートにも反映される）
- **Change Note Type**：既存ノートを別ノートタイプへフィールド対応させながら移行

## 4. カード (Card)
 
同じノートから生成された実体。カードごとに以下の状態・値を個別に持つ。
 
### 4.1 状態（キュー）
| 状態 | 説明 |
|---|---|
| New | 未学習 |
| Learning / Relearning | 学習中・再学習中（短期間隔） |
| Review | 卒業後、長期間隔で復習中 |
| Suspended | 一時停止（出題対象外） |
| Buried | その日だけ非表示（兄弟カード制御や手動埋め） |
 
### 4.2 カードごとのメタ値
- **Due**：次回出題日（またはキュー内順序）
- **Interval**：現在の間隔（日数）
- **Ease factor**（SM-2運用時）／**Stability・Difficulty**（FSRS運用時）
- **Reps / Lapses**：総復習回数・失敗回数
- **Flag（色フラグ）**：手動で赤〜青などの色を付けて分類（学習アルゴリズムには影響しない）
- **Tags**：ノート単位のタグ（検索・Leech管理・AnkiDroid連携等に利用）
### 4.3 カード単位の操作
- Forget（リセットしてNew状態に戻す）
- Set Due Date（任意の日付に強制変更）
- Reposition（新規カードの出題順を変更）
- Find & Replace／Change Note Type（一括編集）

## 5. フィルタデッキ (Filtered Deck)
 
通常デッキとは別枠の特殊デッキ。**検索条件（Search）でカードを一時的に集めて学習**する。
 
| 項目 | 内容 |
|---|---|
| Search | 抽出条件（例：`is:due tag:英単語`） |
| カード数上限 | 一度に集める枚数 |
| Order | 集めたカードの並び順（期限順・ランダム等） |
| Reschedule based on my answers in this deck | チェックを外すと元のスケジュールに影響を与えず一時演習だけ行える |
| 学習後の挙動 [118;1:3u| 元のデッキに戻す条件・タイミング |

## 6. 全体設定 (Preferences / 環境設定)
 
デッキ・ノートタイプを横断するアプリ全体設定。
- **Scheduler**：v3スケジューラの有効化（新しいバージョンでは常時有効）
- **Timezone / Next day starts at**：日付の切り替わり時刻
- **Show next review time**：ボタンに次回間隔を表示するか
- **同期 (AnkiWeb)**：自動同期・強制アップロード/ダウンロード
- **Legacy timezone handling**：旧バージョンとの互換設定
- **バックアップ世代数**：自動保存する `.colpkg` の保持数
- **Reduce motion / ダークモード等の表示設定**
---
 
## 7. 実践的な設定の勘所
 
1. **アルゴリズムは FSRS 推奨**：Deck Options の一番下「FSRS」でON。目標保持率90%からスタートし、レビュー1000件超えたら Optimize で個人最適化。
2. **学習ステップは1日以内に収める**：FSRS導入後は長い学習ステップは非推奨（`1m 10m` 程度で十分）。
3. **1日の新規カード枚数は少なめから**：10〜20枚/日から始め、こなせるようなら増やす。
4. **Maximum reviews/day は絞りすぎない**：低く設定すると復習が繰り越されて雪だるま式に増える「隠れ滞留」を招く。
5. **プリセットは目的別に複数用意**：得意分野・苦手分野・言語系／暗記系など性質が違うデッキは別プリセットにする。
6. **フラグ・タグは学習順序に影響しない**：あくまで人間の分類用。優先度を変えたいときは Reposition や検索抽出（フィルタデッキ）を使う。
