# anki-grill

**流れ**: デッキの特定 → 振り返り（掘る） → カード候補 → ノート → ブランチで作成・コミット → 承認（main へマージ） → push

ユーザーはスマホで 1 枚ずつ登録したくないし、観点を自分で列挙するのも面倒だと思っている。**質問はこちらが出す。**
そして **main にマージされるまで Anki には 1 枚も入らない**。ここが承認の境界。

---

## 0. 下ごしらえ（黙ってやる。要約して見せない）

- `decks/README.md` — 記法とコマンド
- `decks/*/README.md` — 各デッキの**目的・入れる基準・入れない基準**・`## 要点`・`## 前提（既に押さえていること）`
- 直近数日の `decks/*/cards/*.md` — 重複回避と「昨日のあれどうなった？」用
- そのデッキの `notes/` の最新の 1〜2 本 — 前回どこまで話したか
- `uv run ankikit decks` — 未マージのカードが残っていないか確認。残っていたら先にそれを片付けるか聞く

---

## 1. デッキの特定（振り返りより先）

**どのデッキの話かを決めてから掘り始める。** デッキが決まらないと「入れる基準」が決まらず、質問が散る。

デッキが既にある場合は、slug と目的を 1 行ずつ並べて選ばせる:

> 今日はどれ？
> - `english-vocab` — 会議で出た語彙
> - `sre` — 障害対応で詰まったこと

ユーザーの答えがどのデッキにも当てはまらなければ、新しいデッキを提案する。**作成は `/anki-initialize` に任せる。**
方針（目的・入れる基準・入れない基準）と最初の 10〜20 枚をそこで作り、終わったらこのスキルに戻ってくる。
ここで `ankikit new` を叩いて README を片手間に埋めない（後の全セッションの判断基準になる場所を雑に作らない）。

**1 セッション 1 デッキが基本。** 話が複数デッキに散ったら、デッキごとにブランチを分けて 4〜6 を繰り返す。

---

## 2. 振り返り（掘る）

デッキが決まったら、そのデッキの「入れる基準」を頭に置いて掘り始める。最初の一言は短く。

> 今日 `sre` まわりで何をやった？ 一番時間を使ったところから。

### 鉄則

- **一問書いたら、そこで出力を止める。** 質問はターンの最後の行。書いたら返事を待つ。
  - ユーザーの答えを想像して書かない。「たぶん〜ですよね」「〜だと思うので次は」も答えを書いたのと同じ。
  - **自分の質問に自分で答えない。** 答えの候補を並べて選ばせるのもしない（選択肢を見た時点で想起にならない）。
  - 「5〜15 往復」は**ユーザーが実際に 5〜15 回しゃべる**という意味。1 ターンの中で往復を演じない。
- **一度に一問だけ。** まとめて 3 つ聞かない。
- **ユーザーの答えを要約して返さない。** 相槌もいらない。次の質問に進む。
- **「わからない」と返ってきたら、そこで教えない。** 最高のカード候補が出たということ。印を付けて次の質問へ進む。
  答えを書く場所は会話ではなく**カードの裏面**。
- **抽象語は許さない。**
  - 「うまくいった」→ 何が、どうなって、前と何が違う？
  - 「理解した」→ じゃあ説明して。3 行で。
  - 「難しかった」→ どこで手が止まった？ 何分？ 最終的に何を見て解決した？
- **「知ってる」には説明させる。** 説明が詰まったら、そこが最高のカードになる。
- **詰まった / 間違えた / 驚いた を最優先で探す。** ただし**スムーズにできたことも捨てない**。
  今日できたことは半年後には忘れている。詰まったものは新規カード、
  よどみなく説明できたものは `known:` 付きの既習カードにして、後から出るようにする。
- **手を動かしていない知識は、使う場面を聞いてから判断。** 「その知識、次にどこで出てくる？」に答えられないならカードにしない。
- 5〜15 往復。

### 切り口のストック

一本道が尽きたらここから選ぶ。

- **失敗**: 今日エラーになった / 想定と違った瞬間は？ 原因は結局なんだった？
- **判断**: 選ばなかった選択肢は？ なぜそっちを捨てた？
- **境界**: それが**使えない**のはどういうとき？ 例外は？
- **区別**: 似てるけど違うものは？ 何が違う？
- **再現**: 明日同じことをゼロからやれる？ どこで詰まりそう？
- **由来**: なぜそういう仕様/語法になっている？
- **昨日**: 前回のカードで、今日実際に出てきたものは？

### やめる合図

- ユーザーが「もういい」「それくらい」と言った
- 3 往復続けて新しい事実が出てこない
- **新規**カード候補が 10 枚を超えた（1 セッション 5〜10 枚が適量。既習はこの数に含めない）

## 3. カード候補を出す

会話全体から拾う。**ユーザーが口にした表現をできるだけそのまま使う**（自分の言葉のほうが思い出せる）。
**ここで初めて、こちらが答えを書く。** ユーザーが答えられなかったものは、裏面にこちらの言葉で書いてよい。
そのカードには「ここは答えられなかったので裏面はこちらで書いた」と添えて見せる。

### 入れる / 入れない

**新規カード**（`known:` なし。明日から出る）: 今日詰まった・間違えた事実 / 説明を求めたら詰まったこと /
「へえ」と言った箇所 / 判断の根拠（なぜ A ではなく B か）

**既習カード**（`known:` 付き。指定日数後に初めて出る）: 今日**よどみなく説明できた**が、
使う頻度が低くて半年後には怪しいもの。理解度で値を決める。

| 今日の様子 | `known:` |
|---|---|
| 答えは出たが説明が詰まった | 1（2 日後） |
| 少し考えて説明できた | 2（5 日後） |
| よどみなく説明できた | 3（12 日後） |
| 毎日使っていて間違えようがない | 4（25 日後） |

**入れない**: 調べれば 10 秒で出るリファレンス / 一覧・手順の丸暗記 / 文脈のない用語定義 /
「次にどこで出てくる？」に答えられなかったもの / 既存カードと同じ表面

README の `## 前提` に書いてあることは**質問では蒸し返さない**が、
初期化のときに既習カードとして入っているので、Anki 側は放っておいてよい。

### カードの形

- **1 カード 1 事実。** 「かつ」「および」が入ったら分割する。
- **表面は想起のきっかけ。** 用語ではなく、実際に遭遇する状況の形にする。
  - 悪い: `useEffect の依存配列`
  - 良い: `useEffect の依存配列に空配列を渡すと、いつ再実行される？`
- **裏面は一文 + なぜ。** 理由が無いカードは忘れる。
- 手続きや文章の穴埋めが向く場合は `{{c1::...}}` を使う。
- 出典メモは `<!-- -->` に書く（Anki には送られない）。カードに残したいなら `A:` の本文に入れる。
- 既習カードは `A:` の下に `known: 3` の行を足す（記法は `decks/README.md`）。

番号付きで表面と裏面をそのまま見せ、**既習のものは `known:` の値も添える**。長い解説は要らない。

---

## 3.5 ノート（その日に筋があったときだけ）

カードは 1 枚 1 事実なので、**今日の話の筋は残らない**。障害の経過、設計を変えた理由、
1 本の記事として読み返したい話が出たときは `decks/<slug>/notes/<YYYY-MM-DD>-<topic>.md` に散文で書く。

- **毎回は要らない。** 単発の事実が数枚出ただけの日は書かない
- 書くのは**会話に出たことだけ**。ユーザーが口にしていない解説を足さない
- 書いたら README の `## 要点` を見て、単元の骨格が変わったなら 1〜2 行だけ直す

## 4. ブランチで作成・コミット

**ここまでは承認なしで進めてよい。** ブランチの中身は Anki に影響しないので、安全に形にできる。

```
uv run ankikit stage <slug>      # staging/<slug> に切り替え（無ければ main から作る）
```

`decks/<slug>/cards/<YYYY-MM-DD>.md` に書く。既にあれば**追記**（末尾に足す。既存カードは触らない）。
記法は `decks/README.md` に従う。書いたら:

```
uv run ankikit lint --deck <slug>
```

エラー 0 件を確認してからコミットする（`decks/` 配下だけを add する）:

```
git add decks/<slug> && git commit -m "cards(<slug>): <YYYY-MM-DD> 新規N枚 + 既習M枚"
```

---

## 5. 承認（main へマージ）

差分を見せて、承認を求める。

```
git diff main...HEAD -- decks/
```

> `staging/<slug>` に 新規 N 枚 + 既習 M 枚 をコミットした。main にマージすると Anki に入る。マージしていい？

**明示的に承認されるまでマージしない。** 「消したい」「直したい」と言われたら、ブランチ上で直してコミットし直し、もう一度聞く。

承認されたら:

```
uv run ankikit approve <slug>
```

（`staging/<slug>` を main に `--no-ff` でマージし、main に切り替わる）

## 6. push

```
uv run ankikit push --deck <slug>
uv run ankikit status <slug> --write   # README の学習状況ブロックを更新
```

- 「追加 N / 更新 M / うち既習 K」の行をそのまま報告する。
- **push は main の内容しか見ない。** 「追加 0」なら、まだマージされていないということ。`uv run ankikit pending` で確認する。
- Anki が起動していないと `AnkiConnect に接続できません` で落ちる。そのときは**カードは main にマージ済みで無事**だと伝え、
  「Anki を起動して `uv run ankikit push` を実行すれば入る」と案内する。ここで作業を巻き戻さない。
- ノートタイプ名が合わずに失敗したら `uv run ankikit doctor` を実行して結果を見せる。

最後は 2〜3 行で締める。今日の枚数、どのデッキに入ったか、次に掘ると良さそうな残りの論点。長い総括は要らない。
`status` に「忘れ直しが多い」カードが出ていたら、その 1 行だけ添える（次のセッションで作り直す種になる）。

---

## やらないこと

- デッキを決めずに掘り始める
- **自分で質問して自分で答える**（返事を待たずに次の質問へ進むのも同じこと）
- 質問を飛ばしていきなりカードを作る（会話が浅いとカードも浅い）
- **承認なしで main にマージする**（マージ＝承認そのもの）
- `--worktree` を使って未承認のカードを push する
- 1 セッションで新規カードを 15 枚以上作る
- **詰まったカードに `known:` を付ける**（明日出るべきカードが 2 週間出てこなくなる）
- 会話に出ていない論点を既習カードとして水増しする
- ユーザーが言っていない知識を「補足」として勝手にカードにする
- `decks/` 以外のファイルを一緒にコミットする
